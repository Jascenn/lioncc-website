开始前

先准备这三样

01

一个 AI Agent

Codex、ChatGPT 桌面版等能操作你电脑终端的 Agent 都可以。它能读屏幕、跑命令、自己排错，这是整套流程的核心。

02

你自己的 Muse 账号

至少 1 个，想用多账号轮询就准备 2 个以上。必须是你自己注册拥有的账号，不要买或借别人的 Cookie。

03

Chrome 浏览器

导入 Cookie 靠官方自带的 Chrome 扩展完成。每个账号建议用一个独立的 Chrome 用户 profile，避免登录态互相覆盖。

Agent 步骤

把部署交给 Agent

01

打开你的 AI Agent，新建对话

确认 Agent 有权限执行终端命令（Codex 默认就有）。如果是第一次用，直接把下面整段指令原样发给它即可。

请帮我把开源项目 muse2api 部署到本机，要求如下：
1. 克隆 https://github.com/czg86389-hub/muse2api 到本地目录 muse2api-local；
2. 检查 Docker 是否安装并启动，没有就先帮我安装或给出明确指引；
3. 用 docker compose 构建并启动服务，端口只绑定 127.0.0.1:18610，不要暴露到公网或局域网；
4. 生成一个强随机 API Key 保存到 .env 文件，权限设为 600，不要在聊天里显示内容；
5. 启动后验证 http://127.0.0.1:18610/healthz 返回 ok，再打开管理后台 http://127.0.0.1:18610/admin 给我；
6. 把 API Key 复制到我的剪贴板，但不要打印出来；
7. 最后列出还需要我人工完成哪几步。

提示：如果你所在的网络访问 GitHub 或 Muse 较慢，在指令最后加一句「构建下载慢时可以走我本机 7890 端口的代理」，Agent 会自己处理。

02

Agent 自动完成的部分

发出指令后你不用管，Agent 会依次完成：克隆仓库 → 检查并启动 Docker → 构建镜像 → 启动容器 → 生成并保存 API Key → 健康检查 → 打开后台。首次构建要下载浏览器运行环境，几分钟到十几分钟都正常，让它自己跑完。

如果中途报错，不要自己动手改。直接对 Agent 说「看看刚才的报错，修复后继续」，它会读日志、定位原因、重试。
03

验收 Agent 的成果

Agent 说部署完成后，用浏览器打开 http://127.0.0.1:18610/admin。能看到管理后台、剪贴板里能粘贴出 API Key，就说明服务已经跑起来了。不放心的话，再让 Agent 自检一句：

请自检部署结果：确认容器在运行、healthz 返回 ok、端口只监听 127.0.0.1、.env 文件权限是 600，然后把检查结果汇总告诉我。
人工三步

这三步必须你本人做

账号登录和 Cookie 导入涉及你的私密凭证，不要让 Agent 代替，也不要把 Cookie 粘贴到任何聊天窗口里。

04

安装导入扩展并登录 Muse

  • ✓
    加载扩展Chrome 打开 chrome://extensions/，开启右上角开发者模式，点「加载已解压的扩展程序」，选择部署目录里的 extension 文件夹（不确定路径就直接问 Agent：扩展目录在哪）。
  • ✓
    登录账号在这个浏览器里打开 muse.ai 并登录，确认能看到聊天界面。要导入第二个账号，就新建一个 Chrome 用户再登录，互不干扰。
05

一键导入 Cookie

点浏览器右上角的「Muse2API Cookie 导入」扩展图标，填三项：

  • ✓
    服务地址http://127.0.0.1:18610
  • ✓
    API Key直接粘贴，Agent 已经帮你放进剪贴板了
  • ✓
    账号标签随便起，比如 muse-01，方便以后在后台分辨

点「读取并导入」，看到「导入成功」即可。第二个账号换一个 Chrome 用户重复这一步。导入两个以上后，多账号轮询和故障切换自动生效，不需要额外开关。

06

测试账号池，接入你的工具

回到管理后台的「账号池」，给每个账号点一次「测试」，状态变绿就说明这条账号可用。之后在任何支持 OpenAI 接口的客户端里这样填：

Base URL：http://127.0.0.1:18610/v1
API Key：粘贴你的 m2a_ 开头密钥
模型名：muse-spark（对话 / 生图 / 生视频都走这个接口）

最后发一条真实消息或生成一张图验证。想省事就把后台截图发给 Agent，说「帮我确认账号池状态是否正常」。

✓

部署完成

Muse 的算力现在是一个标准的 OpenAI 兼容接口了：48 小时保活自动续期，多账号自动轮询。工具里改两个参数就能用。

常见问题

操作中常见的几个问题

扩展导入失败或缺 Cookie

几乎都是还没登录成功。确认当前 Chrome 用户能在 muse.ai 看到聊天界面再点导入；服务地址结尾不要带 /v1，API Key 要用 m2a_ 开头那个。

构建很慢或下载失败

首次构建要下载浏览器环境，属于正常现象。让 Agent 自己处理：把报错发给它，或直接说「下载慢就走我本机 7890 端口的代理」，不要中途手动删除目录重来。

安全吗？账号会有风险吗？

服务只监听你本机，API Key 和 Cookie 都存在本地。但要清楚边界：这类工具本质是代理网页版算力，请只用自己注册的账号、自用别转卖，并自行评估平台条款风险。LIONCC.AI 仅提供部署教程，与该项目无关。

重启电脑后服务没了

容器默认不会随机启动。开机后对 Agent 说一句「帮我把 muse2api 重新启动并自检」，或者让它顺手把容器设为 restart: unless-stopped，以后就不用管了。
